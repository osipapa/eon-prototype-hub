The Eon Hub design system

Everything the Prototype Hub already decides about color, type, spacing and motion — pulled out of three thousand lines of CSS, reconciled into one set of named tokens, and shaped so it can be typed straight into Figma variables.

3,000 CSS lines 416 .eon-* classes 3 parallel color systems 2 modes

What the code says today

The hub has a real visual language — it is consistent enough that most screens feel like one product. What it does not have is a declared one. The same decision is written down in three places, and the gaps between those places are where the drift lives.

3
Three color systems, none of them the source of truth

The HUB object in prototypes.js drives Hub, Design and Prompts through inline styles. The shadcn HSL variables in index.css drive Tailwind classes and the ui/ components. --route-* in routes.css drives Login and Admin. They disagree: the panel surface is #1A1A1A, #141414 and #151515 depending on which one you ask.

8
Eight font weights, three of them loaded

index.html requests DM Sans at 400;500;600. The CSS asks for 400, 500, 550, 600, 620, 650, 700 and 750. Everything above 600 either snaps back to 600 or gets synthetically emboldened by the browser, so the weight hierarchy the CSS describes is not the one on screen.

20
Twenty font sizes and twenty radii

Sizes run 7, 8, 9, 10, 10.5, 11, 11.5, 12, 12.5, 13, 13.5, 14, 15, 16, 17, 18, 19, 24, 32, 42. Radii run every integer from 2 to 16, then 18, 20, 24, 100 and 999. Twenty-four letter-spacing values and twenty-three gap values sit behind them.

0
Login and Admin have no light mode

routes.css defines --route-* once, on .route-shell, with no light override. The rest of the app follows prefers-color-scheme. On a light Mac, signing in is a black screen and the hub behind it is white.

2
Two typefaces load, one is used by the chrome

The font link pulls DM Sans and Inter. Inter appears only inside the built-in prototype HTML in prototypes.js — prototype content, not hub chrome. It is a render-blocking request for a face the product itself never sets.

!
The one contrast failure

#D98295 is hard-coded as danger text in PrototypeWorkspace.jsx and PrototypeHub.jsx with no light-mode override. On the light panel it measures 2.77:1 — below the 4.5:1 floor, and the only pair on this page that fails. Every other text-on-surface pair in the system passes AA. Proposed light value: #B0243C at 6.64:1.

Color

Neutrals do the structural work; the magenta is a brand cue, never a control color. The dark ladder is four rungs deep so surfaces separate by value rather than by border alone. Light mode is not an inversion — the panel goes white while the page ground drops to a warm-neutral grey, so cards read as lifted rather than cut out.

Figma variables

Three collections, one of which carries the modes. Primitives hold the raw values and never appear in a design directly; semantics alias them and are the only thing a layer should bind to; scales are mode-free numbers. That split is what lets light mode be a mode rather than a second library.

Primitives

1 mode · hidden from publishing
  • neutral/0 … neutral/1000
  • magenta/500, magenta/300
  • blue, amber, green, rose — dark and light pairs
  • alpha/white-*, alpha/ink-*

Open decisions

Six questions this extraction could not answer on its own. Each one is a choice about the product, not a cleanup, so they belong to the team rather than to a refactor.

QuestionWhy it matters
Which color system wins?The HUB object has the most considered ladder and the clearest reasoning in its comments. Making it the source and regenerating the shadcn HSL variables from it would leave one place to edit.
Do Login and Admin get light mode?Adding a light block to .route-shell is a contained change, but it means deciding whether auth screens are chrome or their own world.
Pill buttons or 8px buttons?The auth routes are the only pill-button screens. Either they join the hub or the pill becomes a documented auth variant.
Load 700, or stop using it?33 rules ask for 700 and 12 ask for 750. One extra weight in the font request is cheap; the alternative is that the intended emphasis never renders.
Is 9px text acceptable anywhere?28 rules use it, mostly on tracking-page labels. Raising the floor to 10px changes those layouts.
Does Inter stay in the font link?Only the built-in prototype HTML uses it. Moving it into that prototype's own markup takes it off the app's critical path.
